# S0.2 — De onde vem o status?

- **Tarefa:** F0-T2
- **Data:** 09/11/2026
- **Resultado:** **parcial.** Não há API pública documentada. A extensão oficial e a leitura da interface dependem de verificação do dono (Discord e inspeção da tela logada).
- **Recomendação:** extensão própria (Manifest V3), **somente leitura do que a página mostra**, uma instalação por perfil de navegador/conta. Fallback: entrada manual. Aguarda a decisão do dono.

## Método

Só fontes públicas e sem login. Nada de engenharia reversa do cliente do jogo nem de conexão ao WebSocket dele.

1. Cabeçalhos e HTML público de `https://pokeidle.io/app` (versão do cliente `1.414.1`).
2. Termos de Uso renderizados (`https://pokeidle.io/terms`, versão de 12/10/2026, revisada em 07/11/2026).
3. `robots.txt` do jogo.
4. Site da comunidade `pokeidle-gg.pages.dev`: **não acessível** deste ambiente (o proxy de rede bloqueou o host). Ver S0.3.

## Recomendação

1. **Ponte = extensão própria MV3**, escopo mínimo:
   - `host_permissions` só para `https://pokeidle.io/*` e a origem do hub;
   - content script que **lê** o DOM da aba do jogo quando recebe `sync.request` e monta o snapshot com `null` em tudo que não encontrar;
   - nenhum clique, nenhuma digitação, nenhuma requisição ao servidor do jogo;
   - token de ponte por conta (um perfil de navegador = uma conta = um token), como em `ARCHITECTURE.md` §5;
   - ação extra fora do jogo: "focar/abrir a aba" (S0.1).
2. Se a **extensão oficial** expuser os dados (evento, `postMessage`, armazenamento local legível), preferir ela e evitar manter seletores de DOM.
3. **Fallback manual** (F2-T5 com adapter `manual`) entra de qualquer forma: garante o produto mesmo se o jogo mudar a interface.

## Riscos

- **Fragilidade do DOM:** a interface muda a cada versão (hoje `1.414.1`). Seletores precisam ficar isolados num único módulo, com teste de contrato sobre HTML salvo **pelo dono** e rotulado.
- **Detecção de automação:** ler o DOM não gera tráfego, mas confirme com a equipe que uma extensão de leitura é aceita.
- **Aba em segundo plano:** o jogo só roda com a aba aberta. O navegador pode desacelerar abas ocultas; isso afeta o jogo, não o hub.

## Perguntas para o Discord do jogo (`#open-ticket`)

1. Existe API ou WebSocket de **leitura** permitido para ferramentas pessoais? Se não, uma extensão que só lê a tela da própria sessão e envia a um painel pessoal é permitida?
2. A extensão oficial de automação expõe o estado da conta (nível, hunt, equipe, mochila, boosts) para outras extensões ou páginas?
3. Manter as 4 contas abertas em 4 perfis do mesmo computador, na mesma rede, está dentro do limite (4 por pessoa, 4 conectadas por rede)? Um painel no celular, que **não** abre o jogo, conta como dispositivo?
